# In-Memory Cache with TTL & RWMutex 🧠⚡

Высокопроизводительный потокобезопасный кэш в оперативной памяти (In-Memory Cache) на языке Go с поддержкой механизма ограничения времени жизни записей (Time-To-Live / TTL).

Этот компонент имитирует работу таких систем, как Redis или Memcached, и применяется в высоконагруженных сервисах для кэширования сессий, токенов авторизации или частых запросов к базе данных.

## 🛠️ Архитектура и оптимизация производительности

Основная фишка этого проекта — максимальное быстродействие при преобладающем количестве запросов на чтение данных благодаря использованию **`sync.RWMutex`** (Read-Write Mutex):

1. **Конкурентное чтение (`Get`)**: Метод использует **`c.mu.RLock()`**. Это позволяет сотням и тысячам горутин одновременно и параллельно читать данные из кэша без взаимных блокировок и ожидания в очереди.
2. **Эксклюзивная запись (`Set`)**: Метод использует **`c.mu.Lock()`**. Когда нужно записать или обновить значение, пишущая горутина на долю миллисекунды полностью блокирует кэш как для чтения, так и для других записей, гарантируя консистентность данных.

### ⏱️ Механизм Lazy Expiration (Ленивое удаление)
Вместо того чтобы постоянно гонять тяжелый фоновый воркер и тратить ресурсы на непрерывный перебор всех ключей в карте, в проекте реализован паттерн «ленивой» проверки:
* Время протухания (`Expiration`) рассчитывается в момент записи.
* При вызове `Get` система проверяет, не превысило ли текущее время сохраненную отметку через `time.Now().After(item.Expiration)`. Если данные устарели, кэш просто возвращает `nil, false`, притворяясь, что ключа не существует.

## 🧠 Примененные концепции Concurrency

* **Shared-Memory Synchronization**: Безопасный доступ к встроенной карте (`map[string]CacheItem`) в многопоточной среде.
* **Granular Locking**: Разделение блокировок на чтение и запись для предотвращения образования «бутылочного горлышка» (bottleneck) в коде.
* **Data Encapsulation**: Использование внутренней структуры `CacheItem` для сокрытия метаданных (времени жизни) от конечного пользователя кэша.

## 💻 Имитация сценария в `main`

В коде разыгран классический тест-кейс:
1. В кэш записывается токен сессии со строгим **TTL = 1 секунда**.
2. Метод `Get` запрашивает ключ мгновенно — кэш успешно возвращает «свежее» значение.
3. Программа имитирует паузу и засыпает на **1.5 секунды**.
4. Повторный вызов `Get` возвращает ошибку, так как время жизни токена истекло, и система успешно отсекла устаревшие данные.
