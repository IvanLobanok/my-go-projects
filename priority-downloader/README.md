# Concurrent Priority File Downloader 

Многопоточный менеджер закачек (Worker Pool) на языке Go с поддержкой динамической приоритезации задач и защитой CPU от холостого хода.

Система имитирует скачивание файлов разной важности (например, критические системные обновления vs фоновые медиафайлы), гарантируя, что высокоприоритетные задачи обрабатываются в первую очередь, не вызывая при этом утечек памяти.

## Архитектура и алгоритм приоритезации

В Go каналы по умолчанию «честные» — если объединить их в обычный `select`, выборка будет происходить случайным образом. Чтобы обойти это ограничение и выстроить строгий приоритет, в проекте применен паттерн **Nested Select with Default**:

1. **Первичный опрос (`highPriorityChan`)**: Воркер пытается прочитать файл из канала высокого приоритета.
2. **Запасной план (`default`)**: Если важный канал пуст, воркер проваливается в блок `default`, где вложенный `select` опрашивает низкоприоритетный канал (`lowPriorityChan`).
3. **Защита процессора от 100% нагрузки**: Если оба канала временно пусты (но еще не закрыты), внутренний `default` заставляет горутину уснуть на `20ms`. Это спасает CPU от бесконечного холостого цикла выполнения (busy waiting).

## Примененные концепции Concurrency

* **Priority Worker Pool**: Пул параллельных загрузчиков (`Downloader`), динамически переключающихся на важные задачи.
* **Non-blocking Channel Reading**: Проверка закрытия каналов с помощью флагов безопасности (`file, ok := <-chan`) для плавного выхода из бесконечного цикла без паник и зависаний.
* **Safe State Mutation**: Атомарное обновление общей статистики скачивания (количество файлов, суммарный объем в байтах) через `sync.Mutex`.
* **Prevention of Memory Leaks**: Осознанный отказ от `time.After()` внутри циклов в пользу ручного контроля состояний (`highClosed`/`lowClosed`), что предотвращает утечку скрытых таймеров в оперативной памяти.

## Имитация нагрузочного теста в `main`

В демонстрационном сценарии воркерам скармливается смешанный поток:
1. В очередь залетают 5 обычных картинок (`low`).
2. Внезапно падают 3 критических обновления (`high`).
3. Докидываются еще 3 обычные песни (`low`).

**Поведение системы:** Несмотря на то, что картинки встали в очередь первыми, свободные воркеры мгновенно переключатся и выгребут все критические апдейты из высокого канала, и только после его полного опустошения вернутся к скачиванию песен и обоев.
