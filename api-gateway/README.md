# API Gateway Pipeline with Rate Limiter 

Высокопроизводительный асинхронный Pipeline для обработки входящего HTTP-трафика API-шлюза с ограничением частоты запросов (Rate Limiting) в памяти.
Проект имитирует работу реального межсетевого экрана или API Gateway, который защищает внутренние бэкенд-сервисы от DDoS-атак, брутфорса и спама, отсекая избыточные запросы со статусом `429 Too Many Requests`.

## Архитектура и компоненты системы
Проект построен на базе конкурентных примитивов Go (`channels`, `goroutines`, `sync.Mutex`, `context`) и состоит из 4 ключевых узлов:
1. **Входящий конвейер (`chan Request`)**: Буферизированный канал, куда асинхронно сыплется поток пользовательских запросов.
2. **Пул воркеров (`RequestProcessor`)**: Несколько параллельных горутин, которые одновременно вычитывают запросы из канала, обеспечивая высокую пропускную способность.
3. **Хранилище лимитов (`RateLimiter`)**: Потокобезопасный компонент (на базе `sync.Mutex`), отслеживающий количество запросов каждого пользователя за текущее «окно» времени. Лимит — **3 запроса в секунду**.
4. **Фоновый очиститель (`StartCleaner`)**: Изолированный Background Worker, который с помощью `time.Ticker` ровно раз в секунду сбрасывает счетчики в лимитере, открывая доступ для новых запросов.

## Примененные концепции и паттерны Concurrency

* **Worker Pool Pattern**: Масштабирование обработки трафика с помощью фиксированного пула горутин.
* **Background Worker**: Использование бесконечного цикла `for-select` с тикером для регулярной очистки оперативной памяти.
* **Thread-Safe Storage**: Защита shared-памяти (карт и слайсов) от гонок данных (`data race`) с помощью мьютексов.
* **Graceful Shutdown**: Безопасная остановка воркеров через закрытие канала (`close(ch)`) и синхронизация их завершения с помощью `sync.WaitGroup`.
* **Context Control**: Управление жизненным циклом фоновых задач по таймауту через `context.WithTimeout`.
