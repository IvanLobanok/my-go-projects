# Rate Limiter for API Gateway (Core) 🛡️

Базовый потокобезопасный компонент ограничения частоты запросов (Rate Limiting) на языке Go, работающий в оперативной памяти по алгоритму фиксированного окна (Fixed Window).

Проект демонстрирует фундамент защиты веб-приложений от чрезмерной нагрузки, подбирая оптимальные конкурентные примитивы стандартной библиотеки Go для работы с shared-памятью.

## 🛠️ Архитектура и устройство лимитера

Компонент состоит из двух взаимодействующих частей:
1. **Структура `RateLimiter`**: Хранит карту счетчиков `map[int]int`, где ключ — это `UserID`, а значение — количество запросов за текущую секунду. Доступ к карте жестко синхронизирован через `sync.Mutex`.
2. **Фоновый очиститель (`StartCleaner`)**: Самостоятельный Background Worker, запускаемый в отдельной горутине. С помощью `time.Ticker` он просыпается ровно раз в секунду, полностью сбрасывает (переинициализирует) карту счетчиков и снова засыпает.

### ⚡ Алгоритм работы метода `Allow(userID int)`
* Горутина блокирует мьютекс `rl.mu.Lock()`.
* Проверяется текущее значение счетчика для пользователя.
* Если лимит (например, максимум 3 запроса) превышен — метод мгновенно возвращает `false`.
* Если лимит не исчерпан — счетчик инкрементируется, и метод возвращает `true`.
* Мьютекс гарантированно освобождается через `defer rl.mu.Unlock()`.

## 🧠 Примененные концепции Concurrency

* **Thread-Safe State**: Предотвращение состояния гонки (`data race`) при одновременном обращении сотен горутин к одной встроенной мапе.
* **Background Worker Pattern**: Реализация цикличных фоновых процессов, независимых от основного потока выполнения программы.
* **Resource Leak Prevention**: Корректная остановка тикера через `defer ticker.Stop()`, предотвращающая утечку системных ресурсов после отмены контекста.
* **Context Cancellation**: Использование `context.Context` для изящной остановки фонового воркера при завершении работы приложения.

## 💻 Имитация сценария в `main`

Для проверки работоспособности в `main` реализован последовательный тест:
1. Пользователь совершает 3 запроса подряд — система возвращает `true`.
2. Четвертый запрос от того же пользователя в ту же секунду блокируется системой (`false`).
3. В фоне срабатывает тикер, очищая память и сбрасывая лимиты.
4. Следующий запрос пользователя снова становится успешным (`true`).
